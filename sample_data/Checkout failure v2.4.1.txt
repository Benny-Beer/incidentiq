INCIDENT REPORT
Date: 2024-03-15
Reported by: On-call Engineer Marcus Webb (SRE Team)
Severity: P1
Duration: 41 minutes (15:12 UTC - 15:53 UTC)

INCIDENT SUMMARY
Checkout service experienced elevated error rates beginning at 15:12 UTC.
4,203 transactions failed. Estimated revenue loss: $63,000.
Service recovered after rollback of checkout-service v2.4.1 to v2.4.0.

15:00 UTC - checkout-service v2.4.1 deployed via CI/CD pipeline (automated)
            Release notes: new promo code validation engine, updated payment

ADDITIONAL OBSERVATIONS
- Promo code validation in v2.4.1 calls discount-service on EVERY checkout, even when no promo code entered
- Previous version (v2.4.0) only called discount-service when a promo code field was non-empty
- Redis cache miss rate spike began at 15:14 UTC — 2 minutes after error rate spike (possibly a symptom not a cause)
- Payment gateway SDK updated from v3.1 to v3.2 in this release (changelog: minor retry logic changes)
- discount-service ML model deployment at 14:55 UTC not communicated to checkout team
- 3 of 4,203 failed transactions were charged but not fulfilled (requires manual reconciliation)
- Payment service, inventory service, user-auth service: no errors during incident window
- Traffic volume during incident: within normal Friday afternoon range
- Smoke tests at 15:04 UTC passed because test environment does not call real discount-service

WHAT WAS NOT INVESTIGATED
- Whether payment gateway SDK v3.2 retry logic contributed to thread pool exhaustion
- Whether Redis cache degradation was cause or effect
- Why discount-service SLA breach was not alerted before it caused a customer-facing incident
